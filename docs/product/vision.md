# Vision

## Problem

Working professionals have no easy way to keep a trail of what they do at work. When it's time to update a resume, prepare for a review, or reflect, they try to recall months of work from memory and miss things. The origin of Worklog: documenting an internship only after it ended, and forgetting or never noting key details.

Everything that matters should be logged as it happens, in an organised way: the work itself first, and secondarily the people and emotional side of work.

## Audience

Every working professional, at any seniority, in any field, not only developers. People who already use AI assistants like Claude day to day.

## Solution

A chat-first agent. The user talks through their day, week or month in plain language; the agent organises it into dated, per-Project [Log Entries](../../GLOSSARY.md), asks when something is unclear, and only saves what the user has reviewed and approved.

The agent is the primary surface. Users never need to leave it; chat history, Projects and the Worklog are all browsable in the same UI.

## Principles

1. **Professional first.** Real work is the core. Emotional and office-politics entries are supported but secondary.
2. **Effortless.** Logging should feel so blended into the day that it doesn't feel like overhead. Build discipline through low friction and a daily nudge.
3. **Nothing saved without review.** The agent proposes; the user approves.
4. **Never invent facts.** Anything the agent estimates (for example dates) is clearly marked as an estimate.
5. **Private.** Each Worklog belongs to one user. No teams, sharing or manager visibility in V1.
6. **Nothing is lost.** Entries are archived, never deleted, and every state change leaves a trail.
